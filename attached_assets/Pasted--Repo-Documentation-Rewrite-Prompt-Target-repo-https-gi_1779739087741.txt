## What bpmn-beta looks like

```bpmn-beta
bpmn-beta
accTitle: Purchase Order Approval

pool company "Company" {
  lane requester "Requester" {
    start     s1  "Need Identified"
    task:user t1  "Submit Purchase Request"
  }

  lane manager "Manager" {
    task:user t2  "Review Request"
    xor       g1  "Approved?"
    end       e2  "Rejected"
  }

  lane procurement "Procurement" {
    task:service t3  "Create Purchase Order"
    end          e1  "PO Issued"
  }

  s1 --> t1
  t1 --> t2
  t2 --> g1
  g1 --> t3: "yes"
  g1 --> e2: "no"
  t3 --> e1
}
```

Paste this into the [live playground](https://okhp3.github.io/mermaid-diagram-bpmn/playground)
to see the SVG output.

## BP-SKILL Agent Skill Suite

Skills are the AI analogue of SOPs — executable, version-controlled,
portable instruction sets that auto-activate on semantic match.

BP-SKILL packages the full business process documentation lifecycle as
15 SKILL.md files conforming to the [Agent Skills open standard](https://agentskills.io).

**Compatible with:** Claude Code, OpenAI Codex, GitHub Copilot, Gemini CLI,
Cursor, VS Code, and any other Agent Skills-compatible platform.

### The pipeline

```
LAYER 1 — DISCOVERY
  01 process-intake-and-scope          [core]
  02 stakeholder-and-role-mapping      [core]
  03 elicitation-and-interview-facilitation [core]

LAYER 2 — NARRATIVE
  04 as-is-process-capture             [core]
  05 process-narrative-authoring       [core]
  07 process-gap-and-exception-analysis [core]
  08 future-state-and-change-strategy  [extension]
  10 process-validation-and-quality-scoring [core]

LAYER 3 — VISUAL AND DECISION MODELING
  06 visual-process-modeling           [core]
  09 decision-model-authoring          [extension]

LAYER 4 — OPERATIONAL
  11 process-measures-and-controls-definition [extension]
  12 sop-and-work-instruction-generation [core]

LAYER 5 — GOVERNANCE
  13 raci-and-governance-matrix-generation [core]
  14 sipoc-generation                  [core]

LAYER 6 — PUBLICATION
  15 publication-and-handoff-packaging [core]
```

The central handoff artifact is `PNS.md` — a Process Narrative Specification
that every skill either reads or enriches, creating a validated pipeline
rather than a collection of disconnected prompts.

## What bpmn-beta is — and is not

**It is:**

- A readable DSL for the BPMN 2.0 Descriptive Conformance subset
- Text-first, Git-native, works inside a Markdown code fence
- AI-generatable — designed to be writable by LLMs without syntax repair
- A Mermaid diagram-type contribution proposal (not a commercial product)

**It is not:**

- Executable BPMN — no process engine, no token simulation
- BPMN XML import or export
- Full BPMN 2.0 conformance — choreography, boundary events, transactions,
  and data objects are out of scope for v1
- A production Mermaid plugin yet — upstream contribution comes after
  the DSL stabilises and the Langium parser is built

### docs/adoption-blockers.md

A frank account of what makes BP-SKILL harder to adopt than a simple
prompt template, and what BP-SKILL does about each blocker.
Audience: a technical evaluator or enterprise architect deciding whether
to invest in BP-SKILL.

Must cover all five blockers from the Council research:

  Blocker 1 — Standards licensing
    Problem: BABOK, BPM CBOK, and APQC PCF are paywalled standards.
    BP-SKILL's response: references by section number only, no embedded
    content. check-standards-licensing.mjs enforces this at build time.
    What you need: access to the source standards to work effectively
    with the skills.

  Blocker 2 — Tooling optimised for code, not discovery
    Problem: Agent runtimes (Claude Code, Codex CLI) are optimised for
    code execution and file manipulation. Long-running multi-skill
    business process discovery engagements are not their native mode.
    BP-SKILL's response: all 15 skills are pure text transformations —
    no script execution required. They work identically on every platform.
    What you need: patience with multi-turn sessions for complex processes.

  Blocker 3 — Vocabulary fragmentation
    Problem: BABOK, BPM CBOK, and APQC PCF use overlapping but
    incompatible terminology for the same concepts.
    BP-SKILL's response: the Variable Layer (especially role-dictionary.md,
    process-taxonomy.md, and business-glossary-and-rulebook.md) is the
    bridge. All skills normalise against these files.
    What you need: upfront effort to populate the variable layer correctly.

  Blocker 4 — No existing standard for typed artifact handoff
    Problem: The Agent Skills ecosystem treats skills as independent
    units with unstructured text output. BP-SKILL proposes a pipeline
    with a typed handoff artifact (PNS.md) — a pattern that does not
    yet have a community-accepted standard.
    BP-SKILL's response: PNS.md is the proposed standard. validate-pns.mjs
    enforces it. The metadata.consumes and metadata.produces fields
    declare the contract.
    What you need: to treat PNS.md as a first-class artifact, not just
    a document.

  Blocker 5 — Variable layer configuration overhead
    Problem: 9 context files is a non-trivial onboarding requirement.
    BP-SKILL's response: minimal viable defaults ship with every context/
    template. The generic cross-industry APQC profile and default RACI
    patterns are pre-populated. Variable files are optional unless the
    skills that need them are used.
    What you need: start with organization-profile.md and role-dictionary.md.
    Add others only when the relevant skills are triggered.
