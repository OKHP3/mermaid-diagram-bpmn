# Domain Adapters

The core protocol stays the same. Load only the adapter that matches the
artifact.

## Documents, papers, and reports

Ask whether each major paragraph advances one message, whether claims have
appropriate evidence, whether the conclusion matches the analysis, whether
citations are current and accessible, and whether the intended reader can act
on the result. The disruptor should test overclaiming, source mismatch,
unexamined counterexamples, and accidental author-voice drift.

## Spreadsheets and data evaluations

Check source lineage, schema, formulas, units, missing values, duplicate rows,
filters, joins, date ranges, rounding, denominators, and whether the visual
summary matches the underlying data. The disruptor should construct edge cases,
alternate aggregations, and plausible input corruption. Never overwrite source
data as part of review.

## Outlook or scheduling assessments

Check time zones, date freshness, attendee scope, conflicts, permissions,
privacy, assumptions about availability, and whether recommendations clearly
separate facts from preferences. The disruptor should test a changed
availability, an ambiguous time zone, a private event, and a conflicting
priority. Review does not send, reschedule, or cancel anything.

## Hypotheses and research designs

Check falsifiability, construct validity, operational definitions, comparison
group, sample and holdout design, confounds, measurement error, analysis plan,
and whether the proposed conclusion is stronger than the data can support.
The equilibrium protocol governs review quality; it does not replace domain
appropriate statistical tests.

## Agent Skills

Check discovery precision and recall, activation boundaries, progressive
disclosure, portability, script safety, untrusted input handling, output
contract, evaluation design, holdout protection, and versioned evidence. Never
inherit an older benchmark as proof for a newer skill version.
