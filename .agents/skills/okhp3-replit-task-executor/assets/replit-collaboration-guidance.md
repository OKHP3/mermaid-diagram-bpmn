# Optional project collaboration guidance

Use this wording for a scoped update to an existing project's root `replit.md`
when authorized. Preserve its architecture and other guidance. Replace the
receipt-location placeholder with an actual agreed location accessible to the
receiving operator. Do not copy private task content into a public file.
This template is context for future conversations, not a platform setting,
queue lock, status ledger, or proof that an in-progress Agent saw it.

## Replit and external-agent responsibilities

Replit owns project planning, priorities, requirements, design, styling, UI/UX
specifications, and review of the delivered experience. External coding agents
own architecture decisions, production implementation, technical tests, and
Git integration. Technical suggestions in plans remain proposals until assessed
through the project's decision process.

Keep future plans as planning artifacts until external ownership is established.
Owner acceptance of a plan is distinct from Replit Start or Build dispatch.
Record design references, original acceptance criteria, and dependencies so an
external executor can implement the intended result without guessing.

Read external completion receipts from `<agreed receipt location>` when asked
to review delivered work. A receipt, Git merge, or Markdown status does not
complete a native task. Review the cited revision and return acceptance or a
criterion-specific correction. Route code corrections to the external executor.
Use a supported administrative board action only within existing authority,
with its effects and usage checked first. Preserve cards and return a precise
pending action when that route is unavailable. Do not cancel cards, generate
new follow-ups, or resume coding just to reconcile the board.
