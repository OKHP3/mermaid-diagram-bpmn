# BABOK v3 Elicitation Techniques Reference

This reference covers the elicitation techniques relevant to process discovery, drawn from BABOK Guide v3 Chapter 4 (Elicitation and Collaboration) and the technique descriptions in Chapter 10.

---

## Core Elicitation Techniques for Process Discovery

### Interviews (BABOK v3 §10.25)

**When to use:** When key stakeholders have process knowledge not documented elsewhere; when nuance, context, and exception paths are critical.

**Structure:**
1. Define interview objectives before scheduling
2. Prepare open and closed questions (open first to surface unknowns)
3. Conduct with one or two stakeholders at a time
4. Document verbatim where precision matters; paraphrase where clarity is served
5. Follow up on ambiguities within 24 hours

**Key questions for process discovery:**
- "Walk me through what happens from the very beginning — what triggers this process?"
- "Who else is involved at each step?"
- "What information or materials do you need to start?"
- "What are you handing off at the end, and to whom?"
- "What can go wrong, and what do you do when it does?"
- "Are there any rules or policies that govern decisions in this process?"
- "Which systems do you use, and at which steps?"

**Output quality indicators:** Trigger identified; at least 2 actors named; at least one exception path captured.

---

### Workshops (BABOK v3 §10.50)

**When to use:** When the process spans multiple departments or roles; when stakeholders have conflicting views on the process; when broad scope needs to be covered quickly.

**Structure:**
1. Identify and invite all role stakeholders who participate in or are affected by the process
2. Use a facilitator separate from the note-taker
3. Start with process boundaries: "What starts this process? What ends it?"
4. Walk through the happy path before exceptions
5. Use sticky notes or a process board to build the flow collaboratively
6. Capture dissenting views as open questions, not consensus positions

**Output quality indicators:** All roles represented or explicitly noted as absent; happy path and at least one exception captured; systems identified.

---

### Document Analysis (BABOK v3 §10.14)

**When to use:** When existing SOPs, work instructions, or system documentation exist; when the process is mature and changes are incremental.

**Structure:**
1. Collect existing process documentation (SOPs, flowcharts, training materials, audit records)
2. Map documented steps to observed practice — note gaps
3. Identify business rules embedded in documents
4. Identify systems referenced

**Limitations:** Documents often describe intended process, not actual practice. Supplement with at least one interview to validate.

---

### Observation (BABOK v3 §10.31)

**When to use:** When tacit knowledge is high; when the process is highly procedural; when documentation is absent or outdated.

**Types:**
- **Active observation:** Analyst participates and asks questions while observing
- **Passive observation:** Analyst observes without interrupting

**Output quality indicators:** Steps described at an activity level of detail (not task level); timing and frequency captured if relevant.

## Elicitation Coverage Checklist

For a PIR to be ready for narrative, elicitation must have covered:

| Coverage area | Minimum bar |
|---|---|
| Process trigger | Explicitly stated — what event or condition starts the process |
| Process boundaries | Clear start and end — what is and is not in scope |
| All actors | Each person or system that performs, approves, or is notified |
| Normal path | Happy path steps in sequence |
| Decision points | What choices are made, by whom, using what criteria |
| Exception paths | At least one alternative path — what can go wrong |
| Business rules | Explicit rules governing decisions or constraints on steps |
| Systems | Systems used at each step |
| Controls | Approval gates, audit points, or access controls |
