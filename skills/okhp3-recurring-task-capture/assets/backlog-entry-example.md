Produced when a pattern has been observed but judgment calls still varied
between occurrences — see `../references/backlog-format.md`.

```
- 2026-08-29 | reconcile two AI sessions' conflicting edits to the same repo before reporting to the user | observed: 2 | family: unassigned | status: captured
```

Why this stayed a backlog entry instead of a skeleton: the two occurrences
used different verification steps (one relied on git timestamps, the other
also diffed generated test-count claims against a live re-run) because the
evidence available differed each time. That is still "developing taste" —
see `../SKILL.md` step 2 — not a stable procedure yet.
